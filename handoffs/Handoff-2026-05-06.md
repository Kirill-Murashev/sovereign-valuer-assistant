## 1. Project Purpose

Sovereign Valuer Assistant is an open-source, local-first LLM assistant for valuation professionals.

The project is intended to support, not replace, professional valuation judgement.

Core purpose:

- work with valuation standards, methods, templates, books, and anonymized examples;
- review valuation report fragments;
- distinguish verified facts, assumptions, missing sources, material issues, and minor drafting issues;
- use approved professional memory;
- use local RAG over a knowledge base;
- later use structured valuation data from APIs/local databases;
- reduce token usage by relying on direct verified data tools where possible.

## 3. Architectural Principles

Current fixed principles:

- default LLM: GigaChat;
- initial language: Python;
- local-first deployment: local PC or VPS;
- no heavy agent framework at the current stage;
- no Hermes/OpenClaw/LangGraph/GigaChain/LiteLLM/CrewAI/AutoGen unless explicitly approved later;
- knowledge base and memory are separate;
- approved memory is explicit, inspectable, editable, and user-approved;
- structured valuation data belongs in a separate Data Layer, not only in RAG;
- no uncontrolled self-learning;
- no confidential real valuation reports or client data in the public repository.

## 7. Current Technical Capabilities

### 7.1 Configuration

`app/config.py` loads project settings from `.env` and environment variables.

Current style:

- project-specific variables use `SVA_` prefix;
- GigaChat-specific variables use `GIGACHAT_` prefix.

Important variables:

```env
GIGACHAT_CREDENTIALS=
GIGACHAT_SCOPE=GIGACHAT_API_PERS
GIGACHAT_MODEL=GigaChat
GIGACHAT_VERIFY_SSL_CERTS=false
SVA_KNOWLEDGE_BASE_DIR=knowledge_base
SVA_SKILLS_DIR=skills
SVA_MEMORY_DIR=memory
SVA_DATA_HUB_DIR=data_hub
SVA_CHUNK_SIZE=1000
SVA_CHUNK_OVERLAP=150
SVA_TOP_K=5
SVA_ALLOW_MEMORY_WRITE=false
SVA_ALLOW_NETWORK_TOOLS=false
```

### 7.2 GigaChat

`app/llm.py` contains a minimal SDK-based `LLMClient`.

Important points:

- official `gigachat` SDK is used;
- only provider currently supported: `gigachat`;
- credentials are required;
- unsupported providers raise `LLMConfigurationError`;
- no live LLM calls in tests;
- real GigaChat smoke test passed when using a Russian IP / working route.

Network note:

- Without suitable routing/DNS/IP, GigaChat access may fail with DNS / name resolution errors.
- With Russian IP, smoke test succeeded.

### 7.3 Skills

`app/skills.py` loads YAML skill definitions from `skills/`.

Required skill fields:

```yaml
name:
description:
system_prompt:
user_prompt_template:
```

Current implemented helper:

```python
get_skill_by_name(skills, name)
```

### 7.4 Memory

`app/memory.py` loads required markdown memory files:

```text
memory/user_profile.md
memory/approved_rules.md
memory/rejected_patterns.md
memory/project_notes.md
```

It also formats memory for prompt context.

No memory writes are implemented yet.

### 7.5 Prompting

`app/prompting.py` builds system and user prompts from:

- selected skill;
- approved memory text;
- user input;
- optional retrieved context.

Important rule:

- approved memory and retrieved knowledge context are separated.
- retrieved context is marked as source material, not approved memory.

### 7.6 Local RAG

`app/rag.py` currently implements simple deterministic local RAG:

- load `.md` / `.txt` documents from `knowledge_base/`;
- chunk documents with source metadata;
- retrieve chunks by deterministic keyword-overlap scoring;
- format retrieved context.

Current limitation:

- no embeddings;
- no vector database;
- no BM25;
- no Russian stemming;
- no source display by default, unless the transparent RAG-source patch is applied.
